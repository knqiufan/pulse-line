## 1. 设计原则与目标

### 1.1 核心设计原则

**PRINCIPLE 1 — 零感知性能**
状态栏更新必须在 Claude Code 的 300ms 防抖窗口内完成，用户感觉不到任何延迟。任何可能导致输入卡顿的操作都被禁止。

**PRINCIPLE 2 — 优雅降级**
任何单一数据源失败（git 命令超时、文件读取失败、网络问题）都不能导致整个状态栏崩溃或显示错误。数据缺失时静默隐藏，绝不显示 `???` 或堆栈信息。

**PRINCIPLE 3 — 默认简洁，按需丰富**
默认状态栏只显示 4-5 个最关键的信息段。额外的信息（速率限制、MCP 状态等）默认隐藏，用户可通过配置按需开启。

**PRINCIPLE 4 — 主题与终端共生**
状态栏不假设终端背景色。提供亮色/暗色两套基础主题，用户选择与终端匹配的主题。绝不出现"在亮色终端上显示深色文字"的情况。

**PRINCIPLE 5 — 安装即用，配置可选**
用户只需 `npm install -g` 一个命令即可使用默认配置。高级功能（自定义主题、模块开关、布局调整）通过配置文件实现，非强制。

**PRINCIPLE 6 — 跨平台平等**
Windows (PowerShell/Git Bash/Windows Terminal)、macOS (iTerm2/Terminal)、Linux 用户获得完全相同的体验。不出现"在 Mac 上正常，Windows 上报错"的情况。

### 1.2 成功指标

| 指标 | 目标值 | 测量方式 |
|------|--------|----------|
| 状态栏渲染耗时 | <80ms (P99) | 内置计时 + 日志 |
| 安装到生效时间 | <3分钟 | 用户测试 |
| 跨平台兼容性 | Windows/macOS/Linux 全通过 | CI 测试矩阵 |
| 默认主题可读性 | WCAG AA 对比度标准 | 色彩分析工具 |
| 崩溃率 | 0（零容忍） | 错误监控 |

## 2. 完整功能清单

### 2.1 功能分级体系

功能分为三个级别，用户可根据需要选择性启用：

#### LEVEL 1 — 默认必显（始终显示，不可关闭）

这些是状态栏的核心价值，占用约 60-80 个字符宽度。

| # | 模块 | 显示内容 | 数据来源 | 占用宽度 |
|---|------|----------|----------|----------|
| 1 | **模型标识** | `🧠 Opus` 或 `⚡ Sonnet` | `model.display_name` | ~12 字符 |
| 2 | **上下文进度** | `███████░░░ 65%` | `context_window` | ~25 字符 |
| 3 | **Git 分支** | `🌿 main` 或 `🌿 feat/login` | `git branch --show-current` | ~18 字符 |
| 4 | **会话成本** | `💰 $0.042` | `cost.total_cost_usd` | ~12 字符 |

**总计：约 67 字符 + 3 个分隔符 = ~85 字符**

> 终端最小宽度建议 100 字符，1920x1080 终端窗口足够容纳。

#### LEVEL 2 — 默认可选（通过配置开启）

这些功能提供额外信息，但不开启也不影响核心体验。

| # | 模块 | 显示内容 | 数据来源 | 触发条件 |
|---|------|----------|----------|----------|
| 5 | **会话时长** | `⏱️ 2h 34m` | `session_id` 创建时间 | `showDuration: true` |
| 6 | **工作区名** | `📁 my-project` | `cwd` basename | `showWorkspace: true` |
| 7 | **对话轮次** | `💬 47 turns` | `transcript_path` 解析 | `showTurns: true` |
| 8 | **缓存命中率** | `📦 78%` | `cache_read / total_input` | `showCacheRatio: true` |
| 9 | **思考模式** | `🤔 on` 或 `🤔 off` | `thinking.enabled` | `showThinking: true` |
| 10 | **速率限制** | `⚡5h: ████░░ 45%` | `rate_limits.five_hour` | Pro/Max 订阅者 + `showRateLimits: true` |
| 11 | **7天配额** | `📅7d: ████████░░ 80%` | `rate_limits.seven_day` | Pro/Max 订阅者 + `showWeeklyQuota: true` |
| 12 | **Git upstream** | `↑2 ↓1` | `git rev-list --count` | `showGitUpstream: true` |
| 13 | **Vim 模式** | `-- NORMAL --` | `vim.mode` | Vim 模式启用时（Claude Code 自带，状态栏可增强显示） |
| 14 | **MCP 状态** | `🔌 3 servers` | `~/.claude/.mcp.json` | `showMcpStatus: true` |
| 15 | **输出风格** | `📝 default` | `output_style.name` | `showOutputStyle: true` |
| 16 | **第三方 API 用量** | `🔗 GLM: 63% ████░░░░` | 各厂商 API | `showThirdPartyApi: true` |

#### LEVEL 3 — 高级/实验性（需显式配置）

这些功能可能增加复杂度或依赖外部条件。

| # | 模块 | 说明 | 风险 |
|---|------|------|------|
| 16 | **第三方 API 用量** | 查询各供应商账户余额/用量 | 依赖各厂商 API 稳定性 |
| 17 | **Nerd Font 图标** | 使用更精美的 Nerd Font 图标 | 依赖用户终端字体 |
| 18 | **Powerline 风格** | 使用 `` 等 Powerline 分隔符 | 需要 Nerd Font 或 Powerline 字体 |
| 19 | **子状态栏** | 自定义 subagent 面板行 | 复杂度高，暂不建议 |

## 2.3 第三方 API 用量查询模块

状态栏支持查询主流 AI 供应商的账户余额/用量，让用户在 Claude Code 中一站式掌握所有 API 额度。

### 2.3.1 第一批支持供应商

| 供应商 | 图标 | API 端点 | 认证方式 | 支持的套餐 |
|--------|------|----------|----------|------------|
| **智谱 GLM** | 🇨🇳 | `https://open.bigmodel.cn/api/monitor/usage/quota/limit` | API Token | Coding Plan / API 套餐 |
| **DeepSeek** | 🐳 | `https://api.deepseek.com/user/balance` | API Key | 充值余额、赠金余额 |
| **MiniMax** | 🤖 | `https://api.minimaxi.com/v1/tokens/balance` | API Key | Token Plan / 订阅计划 |
| **小米 Mimo** | 🍃 | `https://api.xiaomi.mimo.com/v1/user/balance` | API Key | API 套餐 |
| **阶跃星辰 StepFun** | 🔭 | `https://api.stepfun.com/v1/account/balance` | API Key | API 套餐 |

> 注：以上 API 端点基于公开文档整理，实际端点可能随厂商更新而变化。系统内置检测机制，当 API 返回 404/410 等错误时自动降级为"不可用"状态。

### 2.3.2 API 查询逻辑

**设计原则：**
- 状态栏查询是**纯展示**操作，不修改任何数据
- 所有 API 调用**默认静默失败**：失败时隐藏该模块，绝不报错
- 用户的 API Key **仅本地存储**，不上传任何第三方服务

**执行策略：**
```
每次状态栏刷新：
  1. 检查配置是否启用了第三方用量查询
  2. 检查 ~/.claude/pulse/api-keys.json 中是否有对应厂商的 key
  3. 检查缓存是否有效（TTL = 5 分钟）
  4. 并行发起所有已配置的 API 查询（带 2 秒超时）
  5. 任一成功则显示，全部失败则静默隐藏整个模块
```

**配置文件 `api-keys.json`：**

```json
{
  "providers": {
    "zhipu": {
      "enabled": true,
      "apiKey": "your-api-key-here",
      "baseUrl": "https://open.bigmodel.cn",
      "planType": "coding_plan"
    },
    "deepseek": {
      "enabled": true,
      "apiKey": "sk-xxxxxxxx",
      "baseUrl": "https://api.deepseek.com"
    },
    "minimax": {
      "enabled": false,
      "apiKey": "",
      "baseUrl": "https://api.minimaxi.com",
      "groupId": ""
    },
    "stepfun": {
      "enabled": false,
      "apiKey": "",
      "baseUrl": "https://api.stepfun.com"
    },
    "xiaomi_mimo": {
      "enabled": false,
      "apiKey": "",
      "baseUrl": "https://api.xiaomi.mimo.com"
    }
  },
  "cacheTTL": 300,
```

### 2.3.5 安全与隐私

- API Key 存储在 `~/.claude/pulse/api-keys.json`
- 文件权限设置为 `600`（仅用户可读写）
- Key 仅用于向对应厂商 API 发起用量查询请求
- **绝不**发送给任何第三方服务
- 用户可随时通过 `/pulse config` 编辑或删除 key

## 3. 技术架构设计

### 3.1 整体架构图

```
┌─────────────────────────────────────────────────────────────┐
│                    Claude Code CLI                           │
│  ┌─────────────────────────────────────────────────────────┐│
│  │  Event: new message / compact / permission change      ││
│  │         ↓ (debounce 300ms)                             ││
│  │  Execute: pulse.command                           ││
│  │         ↓                                               ││
│  │  Pipe JSON to stdin                                     ││
│  └─────────────────────────────────────────────────────────┘│
└─────────────────────────────────────────────────────────────┘
                           │ stdin (JSON)
                           ▼
┌─────────────────────────────────────────────────────────────┐
│              pulse-line (Node.js)                     │
│  ┌─────────────┐  ┌──────────────┐  ┌──────────────────┐  │
```

### 3.3 数据流时序

```
┌─────────┐     ┌──────────┐     ┌─────────────┐     ┌──────────┐
│ Claude  │────→│  Parser  │────→│  Extractors │────→│ Theme    │
│  Code   │ JSON │ (stdin)  │ Obj │  (并行执行)  │ Data │  Loader  │
└─────────┘     └──────────┘     └─────────────┘     └──────────┘
                                              │
                              ┌───────────────┼───────────────┐
                              ▼               ▼               ▼
                        ┌──────────┐    ┌──────────┐    ┌──────────┐
                        │   Cache  │    │   Git    │    │  Config  │
                        │ (检查缓存)│    │ (exec)   │    │ (用户配置)│
                        └──────────┘    └──────────┘    └──────────┘
                              │               │               │
                              └───────────────┼───────────────┘
                                              ▼
                              ┌───────────────────────────────┐
                              │         Formatters             │
                              │  1. 并行提取的数据 → 各段内容   │
                              │  2. 按 order 排序              │
                              │  3. 应用主题颜色 + 分隔符       │
                              │  4. 组合成最终字符串           │
                              └───────────────────────────────┘
                                              │
                                              ▼
                                      ┌───────────────┐
                                      │   console.log │
                                      │   (stdout)    │
                                      └───────────────┘
                                              │
                                              ▼
                                      ┌───────────────┐
                                      │ Claude Code   │
                                      │ 渲染到状态栏   │
                                      └───────────────┘
```

**关键时序要求：**
- Parser + 纯提取器（model, context, cost, workspace）：<5ms
- 带缓存的 git 操作：<10ms（命中缓存）或 <50ms（未命中）
- 主题加载（缓存后）：<1ms
- 格式化 + 输出：<5ms
- **总计目标：<80ms**

## 4. 性能保障机制

### 4.1 三级缓存策略

```
┌─────────────────────────────────────────────────────────────────┐
│                        三级缓存架构                              │
├──────────────┬──────────────┬───────────────────────────────────┤
│    L1 缓存    │    L2 缓存    │           L3 缓存                │
│  (进程内内存) │  (文件系统)   │       (会话级文件)              │
├──────────────┼──────────────┼───────────────────────────────────┤

│              │ Git upstream │                                │
│              │ (10 分钟)    │ 工作区路径                       │
│              │ 配置         │ (15 分钟 TTL)                   │
│              │ (1 分钟)     │                                │
│              │              │ Git upstream 计数                │
│              │              │ (10 分钟 TTL)                   │
└──────────────┴──────────────┴───────────────────────────────────┘
```

### 4.2 超时与熔断

```typescript
// 每个可能有外部依赖的操作都设置超时
const CONFIG = {
  timeouts: {
    gitBranch: 200,        // ms，git branch 命令
    gitUpstream: 1000,     // ms，需要网络的 git 操作
    fileRead: 50,          // ms，配置文件读取
    transcript: 100,       // ms，transcript 解析（如果启用）
    thirdPartyApi: 2000,   // ms，第三方 API 用量查询（2 秒超时）
  },
  cache: {
    gitBranch: 5 * 60 * 1000,       // 5 分钟
    gitUpstream: 10 * 60 * 1000,    // 10 分钟
    workspace: 15 * 60 * 1000,      // 15 分钟
    config: 60 * 1000,              // 1 分钟
    thirdPartyApi: 5 * 60 * 1000,   // 5 分钟（用量变化不频繁）
  }
};

// Promise.race 超时模式
async function withTimeout<T>(promise: Promise<T>, ms: number, fallback: T): Promise<T> {
  return Promise.race([
    promise,
    new Promise<T>(resolve => setTimeout(() => resolve(fallback), ms))
  ]);
}

// 使用示例
const branch = await withTimeout(
  execGit('branch --show-current', cwd),
  CONFIG.timeouts.gitBranch,
  '?'  // 超时时显示 '?'
);
```

### 4.3 性能监控（内置）

```typescript
// 内置轻量级性能监控，仅在调试模式输出
const timings: Record<string, number> = {};

function measure<T>(label: string, fn: () => Promise<T>): Promise<T> {
  const start = performance.now();
  return fn().finally(() => {
    const elapsed = performance.now() - start;
    timings[label] = elapsed;
    if (process.env.PULSE_DEBUG) {
      console.error(`[pulse] ${label}: ${elapsed.toFixed(1)}ms`);
    }
    if (elapsed > 100) {
      console.error(`[pulse] WARNING: ${label} exceeded 100ms!`);
    }
  });
}

// 入口处汇总输出
if (process.env.PULSE_DEBUG) {
  console.error('[pulse] Total timing breakdown:');
  console.error(JSON.stringify(timings, null, 2));
}
```

```typescript
// 用户自定义主题优先级最高
function loadTheme(name: string): Theme {
  // 1. 检查用户自定义主题
  const customPath = getConfig().advanced.customThemePath;
  if (customPath && existsSync(customPath)) {
    return loadCustomTheme(customPath);
  }

  // 2. 检查 ~/.claude/pulse/themes/<name>.json
  const userThemePath = path.join(os.homedir(), '.claude', 'pulse', 'themes', `${name}.json`);
  if (existsSync(userThemePath)) {
    return loadCustomTheme(userThemePath);
  }

  // 3. 使用内置主题
  return getBuiltinTheme(name) || getBuiltinTheme('dark');
}
```

```typescript
// test/benchmark.ts
async function benchmark() {
  const iterations = 1000;
  const input = loadTestInput(); // 标准测试 JSON

  const times: number[] = [];
  for (let i = 0; i < iterations; i++) {
    const start = performance.now();
    await renderPulse(input);
    times.push(performance.now() - start);
  }

  times.sort((a, b) => a - b);
  console.log(`P50: ${times[Math.floor(iterations * 0.5)].toFixed(2)}ms`);
  console.log(`P95: ${times[Math.floor(iterations * 0.95)].toFixed(2)}ms`);
  console.log(`P99: ${times[Math.floor(iterations * 0.99)].toFixed(2)}ms`);
  console.log(`Max: ${times[times.length - 1].toFixed(2)}ms`);
}
```

```
总预算: 100ms（含第三方 API 查询时放宽至 200ms，因为包含 2 秒并行超时控制）
├── stdin 解析 + JSON 解析:              < 5ms
├── 纯数据提取（model 等）:              < 5ms
├── 缓存命中检查:                         < 5ms
├── Git 分支（命中缓存）:                 < 5ms
├── Git 分支（未命中缓存）:               < 50ms
├── Git upstream（命中缓存）:             < 5ms
├── Git upstream（未命中缓存）:           < 100ms
├── 配置加载（命中缓存）:                 < 1ms
├── 主题加载（命中缓存）:                 < 1ms
├── 第三方 API 查询（并行 + 缓存）:       < 10ms（命中缓存）或 < 2000ms（未命中，2 秒超时）
```
